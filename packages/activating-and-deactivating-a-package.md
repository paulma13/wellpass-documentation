# Activating and deactivating a package

## Overview

Every package template has an **Active** or **Inactive** status. You control this with the toggle switch on each row in the Packages tab. Use this when you want to retire a package, pause it temporarily, or bring a previously inactive package back into use.

Receptionists cannot see or use the status toggle.

## How to deactivate a package

1. Go to the **Packages** page in the left sidebar.
2. Click the **Packages** tab.
3. Find the package you want to deactivate.
4. Click the toggle switch in the **Status** column. It switches from Active to Inactive immediately.

No confirmation is required.

## What deactivating does

When you deactivate a package:

- The row appears dimmed in the Packages table.
- The **Assign to client** icon on that row is disabled. Staff can no longer assign the package to new clients.
- If the package was public, it is removed from the Wellpass app immediately. Clients browsing the app can no longer see or purchase it.

**Clients who already own the package are not affected.** Anyone who was assigned or purchased the package before you deactivated it keeps their copy exactly as it was. Their remaining sessions are still valid, their expiry date is unchanged, and they can still use the package for any class or appointment it covers.

## How to reactivate a package

1. Go to the **Packages** page in the left sidebar.
2. Click the **Packages** tab.
3. Find the inactive package (it appears dimmed).
4. Click the toggle switch in the **Status** column. It switches from Inactive to Active immediately.

Once reactivated, the **Assign to client** icon is enabled again, and if the package is public, it reappears in the Wellpass app.

## When to use this

Common reasons to deactivate a package:

- You are replacing an older pricing tier with a new one and want to stop selling the old one without losing its history.
- A seasonal package is only available for part of the year.
- You want to temporarily pause a package while reviewing its settings before re-launching it.

Deactivating is preferable to deleting because it preserves all the historical data about who owned the package and what they paid.
